Replace tsup with tsdown (Rolldown) as the bundler.

This is the structural fix for the "`import.meta` survives in CJS output" bug class: tsup's experimental CJS splitting transpiled esbuild's ESM output with sucrase, which leaks `import.meta` tokens into `.cjs` files (`SyntaxError: Cannot use 'import.meta' outside a module`). tsdown rewrites `import.meta.url` inline per module and splits CJS natively, so the failure mode no longer exists.

Breaking changes:

- Bundler configuration lives exclusively in `libsync.config.mjs` under the new bundler-agnostic key `commands.build.bundler` (object, or `({ type }) => config` function per format). `commands.build.tsup` was removed and now fails config validation with a clear message.
- Standalone bundler config files are no longer read: `tsup.config.{js,mjs}` and `tsdown.config.{js,mjs}` are ignored (a warning is printed if one is present).
- Options are passed to tsdown, so esbuild-specific settings (`splitting`, `esbuildOptions`, `loader`) have no effect — code splitting is native and chunk naming is controlled by libsync.
- JSON source entries are always copied to the output as raw `.json` files instead of being bundled into JS modules (previously this required `loader: { '.json': 'copy' }`). Consumers referencing them directly (e.g. tsconfig `extends`) keep working; importing them as modules from the built output now follows Node JSON-module semantics.

Other changes:

- `entry`, `format`, `outDir`, `watch`, `clean`, `dts`, and `config` are always controlled by libsync; user `outputOptions` and `hooks` objects are merged with libsync's (libsync's chunk naming and internal hooks win on conflict).
- Output layout is unchanged: `esm/*.js`, `cjs/*.cjs`, chunks in `__chunks/[hash]` with the format's extension, `.d.ts` still generated by tsc.
- Watch mode re-copies edited JSON sources and keeps watching JSON-only packages.
- Turbo `build`/`publish:staging` inputs now include `libsync.config.mjs` so bundler config changes bust the cache.
